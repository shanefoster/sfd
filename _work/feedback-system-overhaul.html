The Problem

Entry submission errors were happening at scale, and the impact was concentrated within the most important flow of the product: checkout.

Users would complete the lineup-building steps, attempt to submit, and then get blocked by errors that surfaced only after submission.

{% include insight-callout.html label="The Hypothesis" icon="lightbulb" text="By notifying our members of errors / lineup validations sooner, we can improve lineup submission success rate by x %, and thereby increase NGR by y %" %}

We weren't entirely sure how much this change would improve these stats — but even a 1% lift for each, at our scale, would equate to massive amounts of revenue.

Catalyst

Interface Inventory Audit (Finding the pattern behind the problem)

When I joined PrizePicks, I kicked off an interface inventory audit to map the anatomy of our UI, core patterns, components, and where consistency was breaking down.

As I documented our feedback ecosystem (toasts, inline messaging, alert banners, and system messages), one issue stood out immediately: we were relying heavily on temporary toast messages for user feedback, including cases where users needed to read, understand, and take action. At scale, this created a mismatch between message severity and message persistence. Critical guidance was disappearing before users could resolve the issue.

{% include insight-callout.html label="The Opportunity" icon="lightbulb" text="This audit resulted in our product teams reassessing where, when, and how feedback should appear across key flows, especially in moments tied directly to conversion." %}

Solution 1

Toast redesign

Although the focus of this initative was to focus on persisten Alert Banners, we also took the opportunity to redesign the toasts to be clear, minimal, and accessible. We needed to make sure we leverage our new Feedback token set, and make sure the feedback component system is consisten visually.

Solution 2

Inline, persistent Alert Banners (the real fix)

I introduced inline, contextual Alert Banners that replaced many incorrectly-used toasts, especially in the lineup funnel.

  • arrow_right_alt Trigger based on user action or validation
  • arrow_right_alt Persist until resolved — no disappearing messages
  • arrow_right_alt Sit where the problem is, not floating somewhere else
  • arrow_right_alt Include clear next steps (and CTAs when appropriate)

Solution 3

Feedback tokens + accessibility baked in

We had older/unreleased feedback components, but they were too bland to notice (and the opposite extreme — too branded — also reduced clarity). So we standardized feedback using a Feedback token group:

contrast

Stronger semantic contrast

Error / Warning / Success / Info — each visually distinct and unmistakable.

Consistent iconography

Predictable emphasis and hierarchy across all feedback types.

Accessible color usage

Meets contrast requirements with a predictable hierarchy.

System-level guidance

Feedback feels like guidance, not product decoration.

The Shift

The lineup submission change that moved the needle

The biggest UX failure wasn't just how errors appeared — it was when.

We introduced two new patterns for static alert banners that notify users of changes they need to make before submitting their picks.

The new banners explained:

  • arrow_right_alt What happened
  • arrow_right_alt Why it happened
  • arrow_right_alt How to fix it (with a direct action when possible)
