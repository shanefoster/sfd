The Problem

PrizePicks is in hyper-growth mode, but our operational maturity hadn't kept pace. We lacked a defined design-to-engineering workflow, which created unintentional silos and friction between teams.

Engineers were losing velocity trying to interpret visual intent. To sustain our business growth, I needed to bridge this gap: not just by building a technical solution, but by evangelizing a shared language that united Design and Engineering under a single source of truth.

Infrastructure Refactor

Modual Library Approach

Before diving into the actual tokens, we had to reveiw and assess our setup and infrastructure on both the code and design sides. We were moving at hyper speed. We were constantly experimenting, building new products and features with different needs.

It instantly became clear we had to take a modular approach our library setup to allow flexibility, proper permissions and fewer conflicts.

If teams wanted to have full control of their specific products and brands, they could now branch off this and create their own primitives to build from without conflicts.

Modular structure for more flexibility, control and fewer conflicts.

Guardrails

Variable scoping as a guardrail

As token adoption grew, we added variable scoping to reduce misuse and keep tokens tied to their intended purpose. Instead of treating tokens like a grab-bag of values, scoping lets us constrain where a token can be applied — so teams reach for the right intent by default.

Why it mattered

  • arrow_right_alt Prevents semantic drift: e.g., a "success" token getting reused as a generic green
  • arrow_right_alt Guides correct usage: tokens are discoverable in the contexts they're meant for
  • arrow_right_alt Reduces one-off styling: fewer "closest match" decisions that slowly erode consistency
  • arrow_right_alt Scales governance: the system enforces guardrails so the DS team doesn't have to police every decision

How we used it

  • arrow_right_alt Scoped tokens by intent and surface (e.g., text vs icon vs background) so designers and engineers weren't guessing
  • arrow_right_alt Kept the library flexible, but purposefully constrained — enough freedom to design, not enough to accidentally create new standards

Scoping tokens by surface type (Frame, Shape, Text, etc.) in Figma Variables.

Process

Token governance and change management

Design tokens only work long-term if they're treated like a shared product—with clear ownership, a request path, review gates, and a reliable way to ship changes from design to code.

At PrizePicks, we built a governance workflow that balanced two realities:

brush

Design

Needs a fast, approachable authoring tool — we standardized on Figma Variables.

terminal

Engineering

Needs auditable, reviewable changes — every update lands in GitHub as a PR.
